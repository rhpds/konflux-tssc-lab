== 1. The Supply Chain Security Problem

Building a container image is not the same as trusting it.

In a typical CI/CD pipeline, a developer pushes code, a pipeline builds an image, and that image is deployed.
Fast, repeatable, and completely blind to anything that may have happened between the source commit and the running container.

Supply chain attacks exploit that blindness.
An attacker who can alter the build system, inject a malicious dependency, or swap an image in a registry can deliver harmful software that passes all functional tests.
The artifact looks valid — it just is not what the developer wrote.

This lab addresses that problem directly.
By the end, every artifact you produce will carry three independently verifiable guarantees:

. *Provenance* — the image was built from a known, specific source commit on a trusted build system.
. *Integrity* — no unauthorized party altered the image after the build completed.
. *Policy compliance* — the image passed a defined set of security checks before it was allowed into production.

=== The End-to-End Pipeline

The following stages make up the supply chain you will build and observe throughout this lab:

[mermaid]
....
flowchart TD
    A("Source Commit") --> B("Build — Konflux/Tekton")
    B --> C("SBOM — CycloneDX")
    C --> D("Sign — Trusted Artifact Signer")
    D --> E("Attest — SLSA Level 3")
    E --> F("Policy Check — Conforma")
    F --> G("Release — Production Quay")
....

[cols="20h,~", options="header"]
|===
|Stage |What happens

|Source commit
|You push code to GitLab. A merge request triggers Pipelines-as-Code.

|Build
|Konflux runs a Tekton pipeline that compiles the application and produces a container image.

|SBOM generation
|The pipeline automatically generates a Software Bill of Materials (SBOM) in CycloneDX format, listing every dependency in the image.

|Sign
|Red Hat Trusted Artifact Signer signs the image using a short-lived certificate. The signature is recorded in the Rekor transparency log.

|Attest
|Konflux generates a SLSA Level 3 provenance attestation — a machine-readable record of how, where, and from what source the image was built.

|Policy check
|Conforma evaluates the image against a policy bundle. Only images that pass all checks advance to the next stage.

|Release
|A verified, signed image is promoted to your production Quay organization.
|===

You will build, observe, and stress-test this pipeline across the next seven modules.

== Key Takeaways

* A container image built without signing and attestation cannot be trusted at deploy time — there is no proof of where it came from or whether it was altered.
* SLSA Level 3 provenance proves that an image was built from a specific source commit on a trusted, isolated build system.
* SBOMs enumerate every dependency inside an image, enabling vulnerability tracking and compliance reporting.
* Red Hat Trusted Artifact Signer and Rekor provide the cryptographic infrastructure for signing and a tamper-evident log of every signature event.
* Konflux orchestrates the full pipeline and enforces Conforma policy checks before any artifact reaches production.
* Your tenant namespace is isolated — actions in one namespace do not affect other participants.
